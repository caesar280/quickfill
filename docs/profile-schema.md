# profile.json 字段手册

`profile.json` 是唯一数据源：所有资料、口径、变体都写在这一个文件里，`build_v3.py` 把它灌进脚本模板生成 `*.user.js`。本文档解释每个区块的含义和字段命名约定。示例见 [`profile.example.json`](../profile.example.json)。

## 命名约定

| 约定 | 含义 | 例子 |
|---|---|---|
| `字段_后缀` | 同一字段在不同站点叫法/格式下的变体，脚本按控件类型择优 | `籍贯_三级`、`手机_带区号` |
| `_` 开头的键 | 维护备注，脚本跳过不填 | `_meta`、`_权重`、`_备注` |
| `_三级` / `_二级` | 级联控件（省市区）专用的分层值，`lookupVariantValue` 自动取用 | `浙江省-杭州市-西湖区` |
| `_带区号` | 带国际区号的手机号格式 | `+86 13800138000` |
| `列表项._label` | 该条经历的名字（面板按钮和 `variants` 引用它） | `实习-1 星辰影像（商业摄影·进行中）` |
| `列表项._权重` / `_适用` / `_仅XX岗` | 人肉维护的取舍注记：哪些岗位放哪些条目 | `_适用 = 材料/化工/生产岗` |

## 区块总览

```text
profile.json
├── _meta          版本号、数据来源、冲突裁定记录、使用铁律
├── personal       基础信息（姓名/手机/籍贯/政治面貌…）
├── intent         求职意向（城市/职能/行业/职位/到岗时间）
├── education[]    教育经历（可多条）
├── internships[]  实习经历（可多条）
├── campus[]       校园经历（可多条）
├── projects[]     项目经历（可多条）
├── awards[]       获奖经历（可多条）
├── scholarship    奖学金
├── languages[]    语言与证书
├── skills        技能（按维度组织：专业技能/视觉/内容/数据…）
├── research      科研与实验经历（部分岗位才用）
├── other         备查经历
├── self_eval     自我评价多版本（按岗位与字数取用）
├── variants      岗位差异化配置（见下）
├── manual_fields 永不自动填充的字段（安全红线）
└── files         常用附件的本地路径
```

## variants：一套资料，多岗位口径

`variants` 按**岗位类型**切换口径。投市场岗和投工艺岗，期望职能、首条经历、自我评价、启用哪些区块，都不一样：

```jsonc
"variants": {
  "市场品牌": {
    "匹配岗位": "市场/品牌/营销/管培生（主投方向）",
    "期望职能": "市场营销",
    "首条经历": "projects.项目-2 广告艺术大赛",
    "包含": ["campus", "awards", "internships.实习-1 星辰影像"],
    "排除": ["research"]
  },
  "生产工艺": { "期望职能": "工艺管理", "首条经历": "research.配方设计实验", "…": "…" }
}
```

- `包含` / `排除`：条目级引用写 `区块.条目label前缀`，整区块引用直接写区块名（如 `research`）
- 面板上按 variant 一键切换，脚本替换期望职能/首条经历/自我评价并按 包含/排除 决定哪些区块出现

## manual_fields：安全红线

```jsonc
"manual_fields": {
  "字段名": ["身份证号", "证件号码", "密码", "银行卡号", "证书编号"],
  "需人工操作的动作": ["最终「提交」按钮", "附件上传", "短信/邮箱验证码", "富文本编辑器", "本人签字"]
}
```

命中的字段**永不自动填充**；命中的动作永远人工。这是设计原则，不是可配置项——本脚本只做「把资料填进表单」，不做任何绕过或批量投递。

## 冲突裁定：为什么需要 _meta

同一份资料在不同来源里常互相矛盾（简历上不写 CET 分数、但某表单强制要分数）。`_meta.冲突裁定` 把每个矛盾的**裁定结果**记下来，避免下次填表时重新纠结。示例 profile 里保留了这一节的演示写法。
